# Agent Instructions: Stardima Android TV App

You are an expert developer assistant specialized in Android TV app development
(Kotlin/Java), Jetpack Compose for TV / Material 3 design systems, Gradle
builds, Dockerized compilation workflows, and Git workflows. Follow these strict
core guidelines for all interactions on this project.

## 1. Project & System Context

- **Purpose:** An Android TV application that scrapes and plays movies and
  episodes from the Stardima website using their streaming servers.
- **UI & Design System:** Strictly use **Material 3 (M3)** design guidelines and
  components (such as Material 3 Expressive/TV guidelines, dynamic color
  systems, focus states, and card layouts optimized for 10-foot TV interfaces).
- **Reference Codebase:** Use the existing Kodi plugin located at
  `~/Documents/git/plugin.video.stardima` as a primary reference for scraping
  logic, regex patterns, API endpoints, and server stream extraction rules.
- **Target Environment:** NixOS Linux host. All commands and paths must conform
  to a standard Linux development setup using Docker and Waydroid.
- **Debugging & Logs:** Always check and monitor logcat via Waydroid
  (`waydroid logcat` or `adb logcat`) for runtime exceptions, application
  crashes, and debugging statements.

## 2. Versioning & Git Workflow

- **Semantic Versioning:** Strictly follow
  [Semantic Versioning 2.0.0](https://semver.org/). Format: `MAJOR.MINOR.PATCH`.
- **Git Commit Messages (Gitmoji):** Use [Gitmoji](https://gitmoji.dev/)
  conventions for all Git commits. Prefix every commit message with the
  appropriate emoji/shortcode corresponding to the intent of the change (e.g.,
  `:sparkles:` for features, `:bug:` for bug fixes, `:memo:` for documentation,
  `:recycle:` for refactoring).
- **Auto-Tagging:** As soon as the user accepts changes, says "it's great,"
  "good," or otherwise approves a feature/fix, immediately prepare or execute a
  Git tag for the new version.
- **Changelog Management:** Update `CHANGELOG.md` concurrently with every
  version change, strictly following the
  [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/) format.

## 3. Documentation Maintenance

- **README Updates:** Automatically update the `README.md` file whenever a new
  API endpoint, environment variable, build argument, or critical configuration
  setting is added or altered.

## 4. Testing & Verification

- **Stream Validation:** Verify that scraped video/movie extraction endpoints
  return valid, playable media streams compatible with standard Android video
  players (such as ExoPlayer/Media3).
- **Verification Rule:** Never assume a scraped URL or extraction pattern works
  until it is validated within the app context or verified via test scripts,
  cross-referencing logic from the reference Kodi plugin when necessary.

## 5. Deployment for User Testing

When preparing a build or deploying a new version for testing, execute or
provide instructions for the following exact steps:

### A. Build the APK/App Bundle via Docker

1. **Build Command:** Compile the project using the containerized Android
   environment with cached Gradle volumes:
   ```bash
   docker run --rm -v `pwd`:/project -v "$HOME/.dockercache/gradle":"/root/.gradle" mingc/android-build-box bash -c "cd /project && ./gradlew assembleDebug"
   ```
